# Domain docs

This is a single-context repository. Engineering skills should:

- Read the root `GLOSSARY.md` when it exists. If a root `GLOSSARY-MAP.md` is later added, read the relevant mapped glossaries instead.
- Read relevant decisions in `docs/adr/` before proposing or changing behavior.
- Proceed silently if these files do not exist. Do not suggest creating them upfront; create them lazily when domain terms or decisions are resolved.
- Use glossary vocabulary in issues, proposals, hypotheses, and tests. If a needed term is missing, note the gap for domain modeling.
- Surface conflicts with existing ADRs rather than silently overriding them.
